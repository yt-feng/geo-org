# 每日深度洞察：编辑与生成标准

## 要解决的问题

2026-09-08 核查 GitHub main 最近一篇文章：正文约 1,455 汉字，5 个小节，无分析表格，无文内来源引用。旧流程主要依赖 RSS/Tavily 短摘要，模型失败时会发布通用模板。新流程以一个具体经营决策组织研究与写作。

## 内容验收

中文目标 3,200–4,800 汉字；长度只作为最低完整性检查，不代表深度。每篇需有明确且可检验的核心判断、三个有信息增量的结论、因果机制、业务分群及资源取舍、可复算的指标或经济性示例、反论点与证据局限、负责人/时间/指标/继续或停止条件。

至少读取三份原始正文、覆盖两个出版域；明确行业的选题还必须包含对应行业的正文依据；Tavily/RSS 仅用于找原文。文内引用与已读取资料的 ID、URL 一一对应；不将 AI 合成摘要当来源，不将平台说明当经营效果实证。模型可以提出假设，但必须说明假设，不能虚构采访、客户实绩或实验数据。两张有分析用途的表格需有标题、表头和数据行。

采用独立请求进行研究提纲、草稿、主编审稿，生产失败最多实质修改两轮，之后保留稿件等待恢复。审稿六维为观点、证据、机制、取舍、可执行性、原创性，每维至少 4/5，总分至少 25/30；事实核查须覆盖至少五项不同论断。不达标停止该篇，不发布模板替代品。评分是自动编辑检查，并不代表人工或 BCG 认可。

中文通过后，英文与阿语由 GitHub Actions CPU 上的开源 Hy-MT2-1.8B Q8_0 本地化，仅进行本地可发布性检查，不再请求付费翻译审稿。模型权重和 llama.cpp 运行时固定版本并验证 SHA256。普通用词和语言质量提示不影响发布；中文审稿通过且三语正文完整、HTML及链接有效后写入站点。

生产关闭同次运行的自动跨语言回改（`INSIGHT_CROSS_LANGUAGE_RECOVERY_ROUNDS=0`）。翻译的普通质量差异不会退回中文作者重写，也不会触发整批付费重翻；无法发布的结构或空正文问题保留断点。历史审稿记录仍可显式恢复处理。

## 工作流与维护

日更计划于每天北京时间 02:17 触发（GitHub 排队可能延迟），沿用 Excel 未生成选题和三语输出。每个付费请求还按实际开始时间及最长完成时间检查 DeepSeek 高峰窗口，不仅依赖 cron；会跨入高峰的请求停止并保留已完成内容。生产研究和中文写稿使用 DeepSeek `deepseek-flash`，关闭额外 thinking；独立审稿通过 `INSIGHT_REVIEW_THINKING=enabled` 保留思考。提纲、中文稿、审稿预算分别由 `INSIGHT_RESEARCH_MAX_TOKENS`、`INSIGHT_MAX_TOKENS`、`INSIGHT_REVIEW_MAX_TOKENS` 控制，各为最多 48,000 tokens；提纲要求精简为 1,500–2,200 汉字。每次运行最多 12 个付费请求、600,000 tokens，未知实际用量按完整预留预算计算；分阶段用量保存在 `.artifacts/usage/deepseek.jsonl`。纯翻译不调用付费 API，也没有付费返修或付费兜底。流程：选题 → 原文检索/读取 → 研究提纲 → 写作/审稿/修订 → 开源模型英阿翻译与本地可发布性检查 → 保存 → 提交 main → Vercel Git 集成部署主站；另行触发仓库的 Pages 发布链路。

`generate_daily_blog.py --preview-dir .artifacts/preview` 或 GitHub workflow 的 `preview=true` 生成样稿、保持网站不变。审稿记录在 `.artifacts/insights/<slug>/<lang>.json`，GitHub artifact 保留 14 天；记录原创研究提纲、各轮草稿、审稿与修订回应，以及来源读取边界与正文哈希；网站只保存来源元数据，不保存第三方正文。

默认三次 Tavily 检索分配为两条独立行业查询和一条 AI 搜索平台查询，各用对应的一手出版源域名单。行业来自 Excel 的「行业」字段，不能用发展阶段分类替代。

`RESEARCH_SOURCE_FILE` 可指定选题资料目录（JSON `sources` 数组，条目含 `url/title/tags`）。默认从允许的一手来源域采集；`text_file` 仅用于显式离线测试。源码中的抓取与质量门槛有不可降低的底线。新增出版源需检查正文提取结果和来源适用范围。

本地验证：`python -m unittest discover -s tests -p 'test_insight*.py' -v`。上线核实须核对生成审稿、提交 SHA、对应 Vercel 生产部署及 eco-geo.org 公开文章，Pages 状态或单一绿色生成任务不能证明主站文章已对外更新。

## 参考的研究组织方法

参考 BCG 公开文章对关键结论、研究方法、分群比较、情景与管理行动的组织方式，采用原创论证，不复制其措辞或声称关联：

- [Moving the Agentic Marketing Transformation from Illusion to Reality](https://www.bcg.com/publications/2026/making-the-agentic-marketing-transformation-a-reality)
- [Agentic Scenarios Every Marketer Must Prepare For](https://www.bcg.com/publications/2026/agentic-scenarios-every-marketer-must-prepare-for)
- [Google Search Central: AI features and your website](https://developers.google.com/search/docs/appearance/ai-features)

生成后显式触发部署是因为 [GITHUB_TOKEN 产生的 push 不会触发其他 push 工作流](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)。

Vercel 是主站当前生产部署平台；GITHUB_TOKEN 的限制不能用来推断 Vercel Git 集成未运行。Pages 手动触发仅针对独立的 Pages 链路。

长输出采用 SSE 流式接收，要求正常结束标记与完整 JSON。每 60 秒报告阶段进度，单次请求整体上限 1,200 秒、读取空闲上限 300 秒。输出截断不接受残缺 JSON；在生产最多两次请求内，只允许一次提高输出预算的完整重试（翻倍且不超过 `INSIGHT_LENGTH_RETRY_MAX_TOKENS`，生产 96,000 tokens）。再次截断、达到上限或已用完请求次数则停止，不使用相同预算重复截断请求。中文编辑门槛与三语完整发布要求保持不变。Excel 的 60 个现有行业都有独立中英文检索配置，正文依据仍需每次实际读取与验证。

失败稿可用 workflow 的 `resume_run_id` 指定原生成任务继续修订。程序重新读取原来源并严格核对 ID、URL、正文摘录哈希，保留提纲及全部历史稿件，生产追加最多三次正文修订并重新独立审稿；来源变化则停止续写，要求重新研究。历史事实问题须逐项由审稿确认解决，作者回应格式不会消耗正文修订次数。

定量比较必须统一结果指标、单位、分母、时间窗口和基线，明确使用增量还是总量，包含前置工作成本，并逐个代回验证推荐反转点。禁止用任意权重把错误引用与正确提及合成伪经济性分数；可采用明确标注的示意场景，但不能把引用、点击与收入等同。

每轮修订保留所有历史普通修改意见、结构问题和阻断项，沿用原修订ID；审稿不再提及某项不代表该项自动解决。原始提纲未经独立验证，只保留研究脉络，不能在后续修订中恢复已被纠正的数字。定量写作与独立审稿均核对完整工时账、共同前置工作的成本和产出、修复空间耗尽后的剩余工时、模型期望值与实测整数的区别，以及零值、相等、超预算条件下互斥且完整的行动规则。历史阻断项仍由独立审稿逐项确认，所有质量门槛保持不变。新增差值门槛、不确定区间或平局分支时，作者与独立审稿须分别把每行示例输入代入完整的有序规则，复算最终选项；不能只校验公式而遗漏后续分支推翻推荐。期望值与实测值分别比较，不混合排序。

正文先通过 HTML 解析移除模型生成的内联 style 属性，保留文字、表格、引用和数字，采用站点统一样式；审计记录原始与归一化后正文哈希及处理数量。脚本、事件处理器和不允许的链接仍按结构规则拒绝，内容审稿与最终发布使用同一份归一化正文。

来源日期仅采用语义明确的当前文章发布字段；创建、修改时间及全页任意日期不冒充发布时间。多个发布字段矛盾时日期留空并保留冲突说明，续写也会重新核验日期元数据，正文读取边界与哈希保持不变。

支持对失败稿提交原创编辑修订：指定 `resume_run_id` 与 `editorial_revision_json`，候选稿占一次修订额度，直接进入相同的结构校验与独立审稿，不调用模型重写这一稿；输入中的通过标记或评分无效，历史事实问题仍须逐项复核。候选不通过时才继续剩余模型修订，公开文件在中文审稿通过且英阿正文结构完整后写入。

来源池优先保留一份相关原始实验研究，读取包含实验方法和结果表的明确窗口；Google基线与实际行业正文仍优先，容量不足时行业证据优先于通用论文。论文中的可见度、首引比值比或固定输入实验不能直接外推为农业效果、自然检索提升或收入。论文正文抓取失败按正常流程换源，不用摘要或来源标签充数。

审稿中缺失或无效的引用ID先按原有次数对同一正文重新审稿，纠正证据分类与字段；无支持的论断及仍不合格的审稿继续拒绝。人工提交的原创编辑稿在后续模型续修中作为当前框架，旧提纲只保留研究脉络；所有新增门槛必须与摘要、表格和行动建议一致。

失败或取消的同一生成工作流可从内部审计恢复：来源重新读取并核验正文哈希、读取窗口及元数据；已通过中文稿须重验完整稿件签名、结构、事实核查、六维评分与全部历史阻断项。旧记录缺全稿签名时仅原样独立重审一次。输入编辑修订稿始终重新审稿，译稿仅作本地可发布性检查。

历史审稿恢复兼容（仅处理以前保存的独立审稿记录）：恢复时同时读取同选题、同来源指纹的失败英阿审稿，将其原始记录保存在`cross_language_feedback`中。译稿的阻断项作为待核问题传给中文修订与独立审稿；有尚未复核的问题时，历史中文通过记录不能直接跳过修订。审稿须逐项区分中文原文问题与仅译稿问题，给出当前正文位置、具体发现及解决状态，不能移用译稿分数或通过状态。原中文和译稿历史均保留；问题已被中文独立确认解决后，不会仅因保留历史而反复重写。新译稿记录对应中文全文签名；旧记录只能明确标记为同目录、同选题与同来源的关联。定量审稿另须核对整数计数、百分比分母及严格不等号，并区分平台建议与必要条件、实验比值比与概率。

离线翻译按完整段落、标题和表格单元格分块，保留句子上下文，不将数字与单位拆开。HTML、链接、保护占位符、空输出和明显正文丢失仍检查；措辞、术语、数字格式及语言差异作为非阻断提示。每个完成块实时写入 `.artifacts/offline-translations`，以源稿 SHA256、模型和目标语言绑定；恢复复用已有结果及提示，不重复精修或付费审稿。

`Offline translation and cost controls` 在没有付费 API 凭据的工作流中运行实际英文、阿语 CPU 推理，保留样例结果、模型来源与断点恢复证明。命令为 `python scripts/smoke_insight_offline_translation.py --output-dir .artifacts/offline-smoke`；样例通过结构检查不代替每篇生产文章的独立内容审核。
