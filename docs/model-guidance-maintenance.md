# 模型比较和选型资料维护

公开数据与确定性规则位于 `lib/model-guidance.ts`，不导入服务端配置，也不存放任何厂商源价。核验日为 `GUIDANCE_REVIEWED_AT`；每个来源还保存自己的 `reviewedAt`。

## 新增或更新型号

1. 从当前模型目录取得精确 ID，在模型厂商的官方文档、官方模型卡或官方发布文章核对该版本。不要通过删除日期、`thinking` 后缀或相似拼写推断别名。
2. 通过 `add()` 添加 `ProfileSpec`。填写官方来源 URL、上下文、输入形式与可核验的定位；未核验上下文留空，未核验维度保留 `unknown`。适用性判断用 `editorial`，厂商描述用 `official` 并关联 `sourceIds`。
3. Benchmark 必须保存数据集名称、数字、单位、版本和测试条件（例如推理强度、采样参数、执行工具）。不同条件不合并为统一分数；其他模型的数字不得移植。厂商速度描述不是 tokvilo 实测延迟。
4. 固定日期版本仅在官方明确列出时复用对应能力；已关闭型号设置 `recommendable: false`，仍可在比较页显示历史资料。别名已被重定向且无法确认执行身份时，不注册确定能力档案。
5. 运行 `node --test tests/model-guidance.test.mjs`。测试检查目录 ID、证据来源、明确的可用状态、图片入口、上下文、零售价、不同服务身份、重复行及确定性顺序。

## 调用合同

`getModelGuidance(id)` 找不到精确档案返回 `null`。页面应显示“该版本待核验”，不能退化为同系列其他版本的能力。

`recommendModels(answers, catalog, prices)` 仅使用传入的公开目录与零售价。候选须满足 `available === true`、`category === "text"`、`requestKind === "chat"`，且存在已核验档案。图片输入还要求官方档案与**该平台服务路由**都明确包含 `image`，仅凭模型厂商支持视觉不能推定当前平台已开放。

长材料要求 128,000 输入 tokens，额外预留 1,000 输出 tokens。若传入平台 `contextTokens`，取它与官方窗口的较小者；未知或不足则不推荐。这个静态窗口检查不替代实际请求参数校验。

费用示例由 `guidanceCostExample()` 导出：短任务 2,000 输入 + 1,000 输出；长材料 128,000 输入 + 1,000 输出。调用者应先选择与该上下文匹配的零售价档，再传入 `GuidancePublicPrice`。报价必须与 `modelId + service` 精确匹配；缺失、非法或互相冲突的报价视为未知，不视为零成本。

规则依次考虑任务定位、用户优先级、版本状态，并用稳定 ID 决定相同条件的顺序。省钱模式优先比较上述示例费用，速度/质量是明确标注的编辑偏好，不是实测能力排序。前三个候选先提供不同模型系列，再补同系列选项；同系列替代也必须通过所有可用性和输入筛选。

AI 可用于将用户文字转换成有限问卷枚举；能力事实、价格和最终候选仍由这个规则层生成。目录“可用”和推荐结果都不表示已验证每个型号的真实生成结果。
